## 一、先看结论

- **没有应用账号体系**：不需要注册、登录开发者服务器，也没有用户资料页。
- **没有广告、统计分析、崩溃上报或追踪 SDK**：不接入 AdMob、Firebase Analytics、Crashlytics、Sentry、友盟、AppsFlyer 等；不读取广告标识符，不做设备指纹。
- **黄山学院学号与密码**只保存在本机应用私有目录，密码以 AES-256-GCM 加密；同步时只提交给黄山学院自己的统一身份认证与教务系统，**不会发送给开发者或 Cloudflare、智谱、GitHub 等第三方处理者**。
- **课表、网页导入源、桌面小组件数据默认保存在本机**，不会主动上传。
- **但本应用并非“所有数据都留在本机”**。以下功能会让数据离开设备：
  1. **通用网页导入 / 整学期 AI 导入**：页面可见文本会发送到 Cloudflare 边缘函数，再由其转交智谱 AI（`glm-4-flash`）解析；常见 10–12 位数字（学号格式）会在云端脱敏，但**原始文本仍会先到达 Cloudflare**。
  2. **可选的“上传导入流程”**：学校名称与课表网址会经 Cloudflare 转交 GitHub，创建一个**公开的 Pull Request**。
  3. **常规联网**：更新检查、学校列表、致谢名单、日历导入、打开外部链接等请求，会让相应服务方看到你的 IP 地址、时间与 User-Agent。
- 因此，本政策逐项说明“什么数据、在什么操作下、发给谁”，而不是笼统承诺“绝不上传”。

## 三、本机存储与保护

### 3.1 存储位置

- Android：应用私有目录中的 `SharedPreferences`（通常位于 `/data/data/com.hsu.hsu_schedule/shared_prefs/` 下，实际路径随系统版本与安装方式变化）。未 Root 的其他应用无法直接读取。
- Windows：用户配置目录下的应用数据目录。
- 内置 WebView 的 Cookie 由系统 WebView 组件保存在应用私有存储中，应用通过 `WebViewCookieManager` 读取当前站点的 Cookie。

### 3.2 本地保存的键与内容

| 存储键 / 位置 | 内容 | 保护方式 |
| --- | --- | --- |
| `vault_blob` | 学号 + 密码的 JSON 密文（IV + AES-GCM 密文，Base64） | AES-256-GCM 加密 |
| `vault_key` | 用于上述加密的 32 字节随机密钥（Base64） | 与密文存放在同一私有目录，**未使用 Android Keystore/StrongBox** |
| `username` | 学号（用于界面显示） | **明文** |
| `raw_scrape` | 教务系统返回的原始课表 JSON，可能含姓名、学号、班级 | **明文** |
| `imported_source` | 网页导入的 URL、Cookie、HTML、保存时间 | **明文 JSON** |
| `schedule_widget` | 小组件使用的课表摘要 JSON | **明文** |
| `source_mode`、`last_sync`、`last_update_check`、`login_dismissed`、`compact_widget` | 数据来源、上次同步/检查时间、界面状态 | 明文 |
| 主题、字体、刷新时间等设置键 | 使用偏好 | 明文 |
| WebView Cookie 存储 | 访问过的课表站点 Cookie | 由系统 WebView 管理，位于应用私有目录 |

### 3.3 密码加密的实际强度与边界

凭据保险库的实现参数：

- 算法：AES-256-GCM；
- IV：每次保存生成 12 字节随机 IV；
- 认证标签：128 位；
- 密钥：首次保存时用 `Random.secure()` 生成 32 字节随机密钥，Base64 后与密文一起存入同一个 `SharedPreferences`；
- 明文：`{"username": "...", "password": "..."}`。

这套方案能避免密码以明文形式直接出现在配置文件中，但**不是**硬件级密钥保护：

- 密钥与密文放在同一位置，能读取应用私有目录的攻击者（Root、调试备份、取证工具、恶意系统组件）可以同时取得两者；
- 未绑定 Android Keystore/StrongBox，也未使用用户口令派生密钥；
- 设备解锁后能打开应用的人，可以直接在界面中看到课表，也可以触发同步；应用没有独立的启动密码或生物识别锁。

**清除登录信息**会删除 `vault_blob` 与明文 `username`；`vault_key` 可能保留，但已没有对应密文。

### 3.4 网页导入源未加密

`imported_source` 中的 **URL、Cookie、页面 HTML 均以明文 JSON 保存**，没有像密码那样单独加密。Cookie 可能等同于该课表网站的登录态，请勿在 Root 设备、共享设备或不可信备份环境中使用网页导入。

### 3.5 Android 系统备份

应用的 `AndroidManifest.xml` 未设置 `android:allowBackup="false"`，也未提供自定义备份/数据提取规则。因此在开启系统备份的设备上，应用私有目录中的 `SharedPreferences`（以及 WebView 等应用私有数据目录）可能包含课表、网页导入源与凭据密文，并**可能被纳入 Android Auto Backup 或设备厂商的云备份**。是否备份、备份到哪里、保留多久，由操作系统与你的账号设置决定，开发者无法访问这些备份。

如不希望被备份，可在系统设置中关闭应用备份/云备份，或对本应用排除备份；卸载应用时，已存在于云备份中的数据可能仍按备份服务商的策略保留。

### 3.6 传输安全

- 与黄山学院、Cloudflare、智谱 AI、GitHub、jsDelivr 等服务的请求使用 HTTPS；
- 应用**未实现证书固定（certificate pinning）**，依赖系统信任库；在安装了自定义根证书的网络中，流量可能被中间人查看；
- 应用在 `AndroidManifest.xml` 中设置了 `android:usesCleartextTraffic="true"`，**允许明文 HTTP**。若导入 `http://` 页面，页面内容与 Cookie 会以明文经过网络，可能被同一网络中的他人查看或篡改；请优先使用 HTTPS 站点。

## 四、各功能的网络行为

### 4.1 黄山学院门户同步（原生来源）

涉及域名：

- `https://mwx.hsu.edu.cn`（统一身份认证、信息门户）；
- `https://jwxt.hsu.edu.cn`（教务系统、课表与节次接口）。

流程与数据：

1. 应用向信息门户登录页发起 HTTPS 请求，读取登录所需的 `execution` 参数；
2. 将学号与密码提交到学校登录接口。密码会先按学校门户要求，用写在客户端中的固定 AES 密钥/IV 做一次前端加密再提交。这只是兼容门户登录流程的**前端混淆**，不等同于端到端加密或服务端密码哈希；
3. 登录成功后，通过学校系统的 Cookie 会话请求课表与节次数据；
4. 门户会话 Cookie 只保存在内存中的 CookieJar，**不写入本地存储**；
5. 原始课表 JSON 会写入本机 `raw_scrape`（含姓名、学号、班级），用于离线展示。

学号与密码**只提交给黄山学院系统**，不经过开发者服务器，也不发送给 Cloudflare、智谱、GitHub。学校系统如何记录、保留这些登录信息，适用学校自身的隐私与网络安全规定。

Android 的每日自动同步由 WorkManager 在后台执行；后台任务从本机保险库读取凭据，重复上述请求。若系统限制后台网络，任务可能延后或失败。

### 4.2 网页课表导入与刷新（未适配高校）

- 内置 WebView 打开用户输入或学校预设中的网址。页面由学校网站提供，可能包含第三方脚本、字体、统计代码；这些内容由该网站及其第三方控制，适用其隐私政策。
- 用户点击“读取当前页面并导入”后，应用通过 JavaScript 读取当前页面的 `outerHTML`、可见文本 `innerText`，并通过 `WebViewCookieManager` 读取当前站点的 Cookie。
- 应用只读取页面 HTML 与可见文本，**不专门读取输入框当前值**，因此不会主动抓取用户在网页里输入的密码；但用户在网页中提交的登录信息会直接由该网站接收。
- 应用内置通用 HTML 解析器，用于把本地 HTML 转成课表，它本身不联网。
- 对带有学校类型标记（如 `zf_new` 等）的学校，整学期导入会先使用移植自 Classy 的本地 `zf` 解析器。解析成功**并确认导入**时，页面**不会**上传，弹窗会明确显示“不上传页面”。
- 若用户取消本地解析结果，代码会继续进入 AI 解析；没有类型标记或本地解析失败时，也会进入 AI（见 4.3）。
- 导入成功后，URL、Cookie、HTML 保存到 `imported_source`。之后刷新时，应用向原 URL 发起 HTTP GET，并带上保存的 Cookie；不记录账号密码。

### 4.3 AI 识别（Cloudflare + 智谱 AI）

**触发条件**：网页导入走完整学期流程，且本地解析未成功；或用户使用“未适配高校导入”且没有可用本地解析器。本地解析成功且用户确认导入时不会调用 AI；若用户取消该结果，仍会进入 AI。

**发送路径**：

1. 应用对当前页及后续周次读取 `document.body.innerText`，按周拼接（最多 20 周）；
2. 以 JSON `{"text": "..."}` POST 到 `https://course-table-flow.pages.dev/ai-parse`，客户端最多截取约 30,000 字符；
3. Cloudflare 边缘函数去掉 `<script>`、`<style>`、HTML 标签，将 **10–12 位连续数字**替换为 `[学号已脱敏]`，再截断到约 26,000 字符；
4. 边缘函数把提示词与页面文本发送到智谱开放平台 `https://open.bigmodel.cn/api/paas/v4/chat/completions`，模型为 `glm-4-flash`；
5. 智谱返回 JSON 课程数组，边缘函数清洗后返回应用；应用在本地重新拼成课表 HTML 并保存。

**不会发送给 AI 服务的内容**：Cookie、账号、密码、页面 URL、设备标识。代码中 AI 请求只包含页面文本（翻周导航请求另含控件描述）。

**会发送的内容**：页面可见文字。其中可能包含课程名、教师姓名、教室、上课时间，也可能包含页面上显示的学生姓名、班级、其他数字标识。10–12 位数字会被云端脱敏，但**其他长度或含字母的标识、姓名等不会被自动脱敏**；并且**原始文本在脱敏前已经到达 Cloudflare**。

**翻周导航**：整学期导入需要逐周点击“下一周”。应用会把当前页文本与最多 80 个可点击控件的标签、类型、文字、`aria-label`、`title` 发送到 `https://course-table-flow.pages.dev/ai-nav`，边缘函数截取前约 12,000 字符，再由 `glm-4-flash` 判断应点击哪个控件。该请求同样不包含 Cookie、密码或 URL。

**保留**：应用代码不要求边缘函数持久化页面文本，也不在本地保存 AI 请求原文；Cloudflare 与智谱可能按各自的服务条款、日志与安全策略记录请求。具体保留期限以其政策为准。

**用户选择**：不导入未适配网页、只使用黄山学院原生同步、或在本地解析成功并确认导入时继续，均可避免 AI 请求。应用当前没有“一键关闭 AI”的开关。

### 4.4 可选的“上传导入流程”

从“未适配高校导入”进入并完成网页导入后，应用会询问是否上传该学校的导入流程；也可以稍后在设置中点击“上传已导入流程”。只有用户点击“上传”并确认学校名称后才会发送。

**实际发送的字段**：

| 字段 | 示例 / 说明 |
| --- | --- |
| `school` | 学校名称（用户可修改） |
| `url` | 课表网页 URL |
| `savedAt` | 导入时间（ISO 8601） |
| `appVersion` | 应用版本号（如 `2.0.28`） |

发送到 `https://course-table-flow.pages.dev/`，由 Cloudflare 边缘函数调用 GitHub API：

1. 从主分支（默认 `main`）创建临时分支；
2. 在 `schools/pending/` 写入一个 JSON 文件（含学校名、URL、来源、提交时间）；
3. 创建一个 **公开 Pull Request**，标题与正文包含学校名称和课表网址。

**不会上传**：Cookie、页面 HTML、账号、密码。

**请注意**：

- PR 与仓库内容通常是**公开**的；合并后学校名称与网址会进入公开仓库和“已适配高校”列表；
- URL 的查询参数可能包含会话令牌、学号或其他敏感信息。应用不会自动清除查询参数，上传前请自行检查；
- 上传失败时，应用可能把“学校名 + URL”复制到剪贴板，或打开预填内容的 GitHub Issue；一旦提交，同样属于公开信息；
- 如需删除已提交内容，请通过 Issues 联系维护者；Git 历史与 GitHub 的保留策略可能导致内容不会立即、彻底消失。
- 若维护者在 Cloudflare 上启用了可选的 KV 限流，边缘函数会把来源 IP 作为限流键保存约 120 秒；仓库默认的 `wrangler.toml` 未绑定该 KV。

### 4.5 Google 日历导入

**Android（直接写入）**：

- 通过 Android `CalendarContract` 写入系统日历，不调用 Google Calendar API，也不经过开发者服务器；
- 首次使用请求 `READ_CALENDAR` 与 `WRITE_CALENDAR`；
- 优先选择 `accountType == "com.google"` 的可写日历；若没有 Google 账号日历，则选择第一个可见且可写的日历（可能是本地日历或其他账号）；
- 写入字段：课程名、描述（教师、地点、周次、节次、时间、学分、调课说明）、地点、开始/结束时间、时区 `Asia/Shanghai`、10 分钟提醒；
- 通过“课程名 + 开始时间”判断是否已存在，避免重复插入；
- 若目标日历绑定了 Google 账号，系统会把事件同步到该账号的 Google 日历；这是账号/系统行为，不是应用发起的服务器请求；
- 应用不保存插入后的事件 ID。**删除日历事件需要在系统日历或 Google 日历中操作**，应用内“清除所有课程信息”不会删除已写入的日历事件。

**Windows（导出/跳转）**：

- 生成 `.ics` 文件保存到“下载”或“文档”目录，或通过系统分享面板交给用户选择的应用；
- 可打开 Google 日历导入页；
- “只添加下一节/某门课”会生成 `calendar.google.com/calendar/render?...` 链接，课程名、时间、地点、描述会出现在 URL 中并由浏览器提交给 Google。

### 4.6 桌面小组件

Android 提供 4 类桌面小组件（周课表、下一节、今日、课表）。应用把课表摘要写入本机 `SharedPreferences`，原生 `AppWidgetProvider` 读取并渲染，**不发起网络请求**。

小组件内容显示在桌面上，能看到你桌面的人可能看到课程名、教室、教师与上课时间；锁屏是否显示取决于系统与桌面设置。

### 4.7 更新检查与 APK 下载

- 应用启动时会检查更新，成功检查后 20 小时内不重复；关于页可手动强制检查；
- 首先请求 GitHub Releases API：`https://api.github.com/repos/chengxixian/course-table/releases/latest`；
- 若失败，依次尝试 `version.json`：`cdn.jsdelivr.net`、`fastly.jsdelivr.net`、`gcore.jsdelivr.net`、`raw.githubusercontent.com`、`ghproxy.net` 镜像；
- 发现新版本后，Android 会从 GitHub Release 资产 `course-table.apk` 下载，失败时依次尝试 `ghproxy.net`、`gh-proxy.com`、`mirror.ghproxy.com`、`github.moeyy.xyz` 等公共镜像；
- APK 保存到应用临时目录，通过 `FileProvider` 交给系统安装器；需要用户允许“安装未知应用”；
- 下载只校验大小（大于 1 MB），**没有内置哈希或签名校验**；最终由 Android 安装器校验 APK 签名。公共镜像运营方可以看到你的 IP、User-Agent 与所请求的 URL，其可靠性、日志与隐私做法不受本应用控制。

更新请求不包含账号、课表或设备标识，但会暴露 IP、时间与 User-Agent（`course-table-updater/2.0`）。

### 4.8 学校列表与致谢名单

- 启动时从 `cdn.jsdelivr.net`、`fastly.jsdelivr.net`、`raw.githubusercontent.com` 拉取 `schools/index.json`，用于更新“已适配高校”列表；仅保存在内存，不写入本地；
- “关于”页会从 `cdn.jsdelivr.net` / `raw.githubusercontent.com` 拉取 `acknowledgements.json`，失败时使用内置名单；仅在内存缓存；
- 学校列表请求带有应用版本相关的 User-Agent；致谢请求使用默认 User-Agent；两者都不包含账号或课表，但服务方可见 IP、时间与请求路径。

### 4.9 打开外部链接与分享

- `url_launcher` 会把 URL 交给系统浏览器或对应应用（学校门户、GitHub、Google 日历等），之后的数据处理适用目标网站/应用的政策；
- `share_plus` 会把 `.ics` 文件交给用户选择的分享目标；目标应用会收到课程事件内容；
- 复制学校名/URL 到剪贴板只在用户点击“复制信息”时发生。

## 八、数据保留与删除

### 8.1 本机数据

| 想删除的内容 | 操作路径 | 结果 | 仍会保留 |
| --- | --- | --- | --- |
| 课表、网页导入源、小组件显示 | 设置 → 课程数据 → **一键清除所有课程信息** | 删除 `raw_scrape`、`imported_source`、`source_mode`、`last_sync`，并把小组件清空 | 登录凭据、应用设置 |
| 网页导入源 / Cookie | 同上；或设置 → 课程数据 → **恢复黄山学院原生课表** | 删除 `imported_source` 与 `source_mode` | 原生课表（若有）、凭据 |
| 学号与密码 | 设置页 → “关于”区块 → **清除登录信息** | 删除 `vault_blob` 与明文 `username` | `vault_key`（无密文可解）、课表、设置 |
| 应用设置、更新时间等 | 系统设置 → 应用 → 课程表 → **清除数据** | 删除全部应用私有数据 | 系统备份中的副本（若有） |
| 全部本地数据 | **卸载应用** | 删除应用私有目录 | 系统/云备份中的副本（若有）；已写入的日历事件；已提交的公开 PR |

清除操作立即在本机生效，但**不可撤销**。删除后需要重新登录/重新导入。

### 8.2 应用之外的数据

| 数据 | 如何删除 |
| --- | --- |
| 已写入系统/Google 日历的课程事件 | 在系统日历或 Google 日历中手动删除；应用不会自动删除 |
| 已上传的学校流程 / PR | 通过 [GitHub Issues](https://github.com/chengxixian/course-table/issues) 联系维护者；Git 历史可能仍保留 |
| Cloudflare / 智谱 / GitHub / CDN 的日志 | 由各服务商按其隐私政策与保留期限处理；开发者无法直接删除 |
| 系统备份中的副本 | 在系统/云备份设置中删除对应备份，或等待备份服务商按策略过期 |

### 8.3 没有“账号”可注销

本应用没有开发者账号体系，因此不存在“注销账号”的入口。删除本机数据或卸载应用即可停止本地处理；已发生的第三方传输按第八节与各服务商政策处理。
